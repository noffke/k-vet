# API Contract: REST Endpoints

**Date**: 2026-07-26 | **Spec**: [../spec.md](../spec.md) | **Data model**: [../data-model.md](../data-model.md)

The **binding contract artifact is the OpenAPI spec generated by utoipa from the Axum
handlers**, committed at `k-vet-backend/openapi.json`, from which the TS client
(`k-vet-web/src/api/generated/`) is generated via orval. CI regenerates both and fails on diff.
This document is the design-time inventory the handlers must implement.

Conventions:

- Base path `/api`; JSON bodies; errors as RFC 7807 `application/problem+json`.
- All endpoints except `POST /api/auth/login` require the session cookie (401 otherwise).
- Variant entities (packagings, movements, treatment items, attachments) are tagged unions
  discriminated by `kind`/`type`/`status`.
- List endpoints: `?q=` (text filter), `?archived=true` to include archived (default excludes),
  `?limit=&offset=` where lists can grow unbounded; used by tables (desktop) and cards (mobile).
- `PATCH` endpoints accept partial bodies — they are the auto-save write path (all fields
  optional; only present fields change).
- Mutations return the updated resource so TanStack Query can update its cache directly.
- **Locale-independent wire format**: dates/timestamps are ISO 8601, numeric values use
  dot-decimal strings/JSON numbers. All locale-aware formatting and input parsing (decimal
  comma, date formats, currency display) is exclusively a client concern — it never crosses
  the contract boundary.
- **Draft rows**: `POST /api/{resource}` on form-edited entities creates a draft immediately
  (the auto-save target); resource responses carry `draft`; the server recomputes the flag on
  every PATCH (no explicit "complete" endpoint). List endpoints include drafts flagged as
  incomplete; the picker and billing flows exclude them.
- **Contact-data validation**: email fields are declared `format: email` in the
  utoipa-generated OpenAPI, so orval's zod schemas validate them client-side too; phone
  numbers are parsed/normalized server-side (default region DE, stored E.164, returned with a
  national display form). The server is authoritative: invalid input → 422 `problem+json`
  with field-level details; client-side zod is UX sugar.

## Auth
| Method & Path | Purpose |
|---|---|
| `POST /api/auth/login` | `{username, password}` → sets session cookie |
| `POST /api/auth/logout` | destroys session |
| `GET /api/auth/session` | current session info (for app boot) |

## Unified picker
| Method & Path | Purpose |
|---|---|
| `GET /api/picker/items?q=` | full-text search over drug packagings + services; ranked by nightly usage then similarity; returns tagged union with display name, price, kind icon hint. Excludes hidden/archived. |

## Master data (uniform CRUD pattern)
Pattern for `customers`, `patients`, `suppliers`, `manufacturers`, `services`,
`treatment-templates`, `drugs`:

| Method & Path | Purpose |
|---|---|
| `GET /api/{resource}` | list (filter/pagination/archived flag) |
| `POST /api/{resource}` | create (returns row with id — auto-save target) |
| `GET /api/{resource}/{id}` | detail |
| `PATCH /api/{resource}/{id}` | partial update (auto-save) |
| `POST /api/{resource}/{id}/archive` / `.../unarchive` | soft delete / restore |

Resource-specific additions:

| Method & Path | Purpose |
|---|---|
| `GET /api/customers/{id}/patients` | patients of a customer |
| `POST /api/customers/{id}/emails` / `PATCH,DELETE /api/customer-emails/{id}` | typed email addresses |
| `GET /api/patients/{id}/files` / `POST /api/patients/{id}/files` | patient files (reference date, note) |
| `PATCH /api/patient-files/{id}` | edit reference date/note |
| `GET /api/drugs/{id}/packagings` | packagings of a drug |
| `POST /api/drugs/{id}/packagings` / `PATCH /api/packagings/{id}` | manage packagings; server computes `sales_price_net` (AMPreisV, rule per `drug.human_drug`) on list-price/VAT/flag change unless overridden |
| `POST /api/pricing/preview` | `{list_price_net, vat_percent, kind, quantity…}` → computed gross price (UI live preview) |
| `GET /api/treatment-templates/{id}/items` + `POST/PATCH/DELETE` item endpoints | template items |
| `POST /api/template-items/{id}/move` | `{direction: up\|down\|top\|bottom}` position change |

## Pharmacy stock
| Method & Path | Purpose |
|---|---|
| `POST /api/packagings/{id}/stock-intakes` | record intake → creates lot (snapshot initial quantity) |
| `GET /api/lots?packaging_id=&drug_id=` | lots with derived remaining stock |
| `GET /api/lots/{id}` | lot detail: chronological movements, each linking dispense → treatment/invoice/customer or correction reason |
| `POST /api/lots/{id}/corrections` | correction movement `{quantity (default: remaining), reason}` |
| `GET /api/stock/correction-reasons` | distinct previous reasons, alphabetical (editable-select source) |

## Appointments & treatments
| Method & Path | Purpose |
|---|---|
| `GET /api/appointments` / `POST` / `GET,PATCH /{id}` / `DELETE /{id}` | CRUD (delete allowed while no invoiced treatment) |
| `POST /api/appointments/{id}/duplicate` | `{price_mode: verbatim\|refresh}` → copy, date = today |
| `POST /api/appointments/{id}/treatments` | add treatment to appointment |
| `GET,PATCH /api/treatments/{id}` | treatment detail (reason, finding, patients set) |
| `POST /api/treatments/{id}/duplicate` | same `price_mode` option |
| `GET /api/treatments/{id}/items` / `POST` | list/add items; server pins name/price/VAT/factor/GOT number at insert; drug items write draft FEFO dispense movements |
| `PATCH /api/treatment-items/{id}` | edit line (qty, overrides, patient, km) → draft movements recalculated |
| `DELETE /api/treatment-items/{id}` | remove line (draft movements removed) |
| `POST /api/treatment-items/{id}/move` | position up/down/top/bottom |
| `POST /api/treatment-items/{id}/lots` | override FEFO lot selection `[{lot_id, quantity}]` |
| `POST /api/treatments/{id}/apply-template` | `{template_id}` → append items in order, current prices/names |
| `GET,POST /api/treatments/{id}/files` | treatment file attachments |

## Invoices
| Method & Path | Purpose |
|---|---|
| `POST /api/treatments/{id}/invoice` | create (or update-recreate) invoice `{includes_finding, note}`; allocates/keeps number per rules; renders PDF; → status `created` |
| `GET /api/invoices` | list; accepted-not-submitted first; `?status=`, excludes cancelled by default |
| `GET /api/invoices/{id}` | detail incl. lifecycle timestamps |
| `GET /api/invoices/{id}/pdf` | stream the PDF |
| `POST /api/invoices/{id}/accept` | `{recipient_emails[]}` → freeze dispenses, email PDF (CC/BCC from settings), ts_accepted; ts_sent_email on SMTP success |
| `POST /api/invoices/{id}/send` | re-send the invoice email to the stored recipients (retry after failure or repeat send); ts_sent_email updated on success |
| `POST /api/invoices/{id}/cancel` | → status cancelled, ts_cancelled, compensating stock corrections |
| `POST /api/invoices/{id}/submit` | mark submitted to bookkeeping |
| `POST /api/invoices/bulk-submit` | mark all accepted-not-submitted as submitted |
| `GET /api/invoices/pending-pdfs` | ZIP of all accepted-not-submitted PDFs (bulk download) |

## Attachments (shared)
| Method & Path | Purpose |
|---|---|
| `POST /api/attachments` | multipart streaming upload → `{id, sha256, …}` (hash-while-stream, atomic rename, dedup) |
| `GET /api/attachments/{id}` | stream content (`Cache-Control: immutable`) |
| `GET /api/attachments/{id}/thumbnail` | image thumbnail |

## Dashboard & settings
| Method & Path | Purpose |
|---|---|
| `GET /api/dashboard` | `{unsubmitted_invoice_count, expiring_lots: top 5 with stock}` |
| `GET /api/settings` / `PATCH /api/settings` | single-row global settings (auto-save) |
